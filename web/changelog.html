Changelog & progress

What has been built, in order. Source: docs/PROGRESS.md in the repo.

MilestoneDateWhat changed
M02026-10-03Housekeeping: git, .gitignore, removed a mock scipy that was corrupting renders, gold-example MANIFEST, pytest.
M12026-10-03Port API (named connection points, orthogonal Connection routing) and the 6-check geometric linter with baselines and 6 broken fixtures. Fixed the Banner dim-text bug.
M1.52026-10-03End-to-end benchmark, v2 vs v3, on Darjeeling. Lint passing did not mean the animation matched the spec, which led to spec conformance checks and transient-packet rules.
M1.62026-10-04Polish (text sizing, margin labels, wires avoid blocks, 1920x1080) and a second chip, Earlgrey: 40/40 blocks, 39/39 wires, 0 errors.
M1.72026-10-04A third chip, Peppermint: every one of its 24 blocks and 9 edge labels drawn, all 32 certain wires, 3 regions, and zero problems from either automatic check. The same engine, no new drawing code. It forced five general fixes: a picture with no legend, a box the picture never labels, edge labels on three sides instead of one, the step panel keeping its minimum width, and a region title that no longer sits on the blocks beneath it. Darjeeling and Earlgrey re-run unchanged.
Example library2026-10-05Four new reference animations, each teaching the generator a shape the chip diagrams cannot: a systolic array built from a loop, a MESI state machine with curved and self-looping arrows, a mirrored dual-core lockstep, and a compute-in-memory crossbar where the blocks are the wire intersections. Every structure is taken from published work and cited, and every one passes the geometric checker with no errors and no warnings. Also: domain titles now shrink to fit their own box, so they can no longer run across the blocks underneath, and the animations are paced slowly enough to read.
Explainer2026-10-04The "how it works" video on the home page was made by IPMotion itself: hand-written against the same library the generator writes against, and passed by the same geometric checker, with no errors and no warnings.
RAG quality2026-10-04Measured what the Generate button actually produces, by replaying the exact prompt the browser sends and scoring the result. Added a full worked example (a real 40-block chip) to what the model reads, and told it to copy your block names character for character. Things drawn that were not asked for dropped by about half.
Web2026-10-04This static site: BYOK generator, how-it-works page, changelog.
M2 to M6PlannedStyle conventions, LLM layer and run logging, ordered repair loop, vision critique, approve CLI and incremental indexing.

Known limits

  • Fidelity numbers compare drawings with hand-written notes of each picture, not with the picture itself.
  • Lint snapshots end states only; mid-animation overlaps are not checked.
  • Reading a new diagram image automatically (vision) is not built yet.
