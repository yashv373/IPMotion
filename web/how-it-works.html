How it works

IPMotion treats a diagram animation as something a program can measure. A model proposes; geometry and a renderer check. This page describes the full local pipeline, and what this website skips.

1. Source of truth

Architecture facts come from hand-transcribed truth files (YAML: blocks, domains, connections, fills), never from a model's memory. A layout file adds pixel boxes detected from the reference picture's fill colours, plus hand-read wire routes. Truth files are never indexed or put in prompts, which protects the benchmark from leaking.

2. Schemas and validation

spec_validator checks a spec against a schema: unique ids, connections that name real blocks, nested domains, scope: full for whole diagrams, and an explicit unconfirmed flag for things the picture does not make clear. Unclear items are drawn amber-dashed and listed for a human to confirm, never silently dropped.

3. Library and ports

ipmotion_lib.py provides IPBlock, DomainGroup, Banner, gate/symbol classes and a port API. A Port is an invisible named point with an outward side, so Connection(src_port, dst_port) routes orthogonal wires (straight, Z, around, U-turn). Library changes are additive and checked against recorded golden geometry.

4. Renderer-in-the-loop

Instead of trusting generated code, the engine runs it. A worker subprocess executes the scene with play()/wait() patched, and snapshots every mobject's geometry after each one. No video is encoded, so a lint pass takes seconds. Only then is a real render made.

5. Geometric linting

CheckCatches
text_overlapTwo labels sharing pixels
text_occludedText hidden under a later-drawn block
dangling_endpointWires that end in empty space
out_of_frameContent clipped by the frame
min_spacingBlocks too close or overlapping
min_text_sizeLabels too small to read at 1080p

Thresholds live in style.toml. Travelling packets are transient and skipped by the spacing checks.

6. Spec conformance and fidelity

Passing lint does not mean the animation matches the diagram. conformance.py compares the drawn snapshots with the spec: every label drawn, domain members inside their region, every connection with the right arrowheads, no extra blocks, banners in order. fidelity.py scores blocks, regions, wires, extras and left/right/above/below order. Repeated names (the same block per power domain) are paired by reference order.

7. Repair loop (feedback order)

Runtime errors first, then spec conformance, then lint, at most five grouped items per attempt. Spec errors are structural, so fixing layout before the right blocks exist is wasted work. This is the "aesthetics before logic" rule applied to model feedback.

8. Two generation modes

v3 (this website): the model writes a whole Manim script against the library. v4 (local): code draws the whole diagram from truth + layout, and only the story varies, so the diagram is deterministic.

What this website does

Context stuffing: it fetches four static text files (rules, library API, one verified gold example, notes), appends your story and diagram text, and sends one request from your browser to your provider. No lint, no conformance check and no repair loop run here. Run python -m ipmotion.lint script.py locally to get them.
