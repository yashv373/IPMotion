RULE 2 -- WIRES GO BEHIND BLOCKS, AND BLOCKS GO ON TOP.
Add every wire to the scene BEFORE the blocks it connects, so a wire that passes over a block is hidden by it

between, and the reader cannot tell which blocks it actually joins.

RULE 3 -- USE wire() FOR EVERY CONNECTION. DO NOT DRAW ARROWS YOURSELF.
The library routes wires around blocks for you. You cannot do this by hand: an Arrow between two blocks is a
straight line that runs over everything in between and hides those blocks' names.

    blocks = [ibex, crossbar, sram, uart]          # every block in the drawing
    self.add(wire(ibex, crossbar, avoid=blocks))   # routed around anything in the way, drawn behind the blocks

  - Pass avoid=<the list of every block you created>. The wire's own two ends are ignored automatically.
  - heads="to" puts an arrowhead at the target (default), "both" for bidirectional, "none" for a plain link.
  - wire() already sets z_index so the wire sits behind the blocks. Do not re-add it on top.
  - Only fall back to Arrow() when you genuinely want a free-standing arrow with no block at one end, such as an
    edge label pointing in from outside the diagram.

RULE 4 -- EVERY LABEL MUST BE READABLE AT A GLANCE.
Edge labels ("External memory port for the CPU", "Entropy input") are the first thing a reader looks for
and the first thing that ends up unreadable. Use font_size 16 or more for any free-standing label outside a
block, and never below 14 anywhere. If a label does not fit, break it over two lines rather than shrinking it.
A block's own title is handled for you: IPBlock breaks a long title over up to three lines, never shrinks it
below readable, and writes it vertically along a tall narrow block (a bus bar). So give a bus bar a real width
(0.4 or more) and let the library do the rest -- do not pre-shrink a title yourself, and never pass
min_font_size: it exists only for the whole-chip renderer and turns these guarantees off.

generated so far. Only use DomainGroup directly when there is nothing inside the region to measure.
